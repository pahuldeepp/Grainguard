Design records: [ADR-0006](../docs/adr/0006-ingest-quality-and-lateness.md), [ADR-0007](../docs/adr/0007-ingest-rate-limiting.md); endpoint reference: [INGEST_API.md](../docs/INGEST_API.md).

Found and fixed during this stage: the OTLP exporter posted to `/` instead of `/v1/traces`; the `source_message_id` rule was looser than the event contract; a request with malformed correlation metadata would have failed inside the database instead of being refused up front.

Known limits: rate-limit buckets are per pod, with the shared Redis tenant limit planned for Stages 08 and 13; `/metrics` is unauthenticated and must be exposed only on an internal network; no transport delivers inventory events yet, so tests seed device bindings by applying events directly (Debezium and Kafka are Stage 04); the ingest endpoint has no `API-Version` header because versioning is centralised at the gateway in Stage 08; staging runs the health probes only.
